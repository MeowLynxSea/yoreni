# Session removal: implementation inventory

The approved target removes conversation sessions, including all compatibility routes. Existing personal databases and backups are not deleted or automatically imported. The implementation below is complete; remaining `session` names in the inventory are historical records or independent technical sessions, not chat-session runtime code.

## Ownership and order

1. Keep AgentStore as the owner of identity, revisioned preferences/tasks, events and Run records. Remove automatic legacy history import and the personal Session projection. Recent model context selects completed user Runs directly; checkpoints stay on each Run.
2. Reduce AgentLoop to runtime/tool composition, event dispatch, cancellation and shutdown. Move portable checkpoint recovery and transcript compaction values into agent modules. Remove session restore/save, autocompaction queues, generations and session routing. Goal tools access AgentStore only.
3. Make API and SDK use AgentInput exclusively. Reject obsolete API parameters; remove SDK session clients and snapshot/import/export operations. Ephemeral is a Run execution option.
4. Migrate Heartbeat, Dream, Cron, local triggers, hooks, shell ownership and output dispatch to explicit source, authority, destination and Run IDs. External inputs require an explicit trust grant before personal state or memory access.
5. Replace WebUI session admission, history, paging, creation, switching, fork, temporary-chat and recovery adapters with authenticated event submission and Run lifecycle frames. Keep settings, media, model, tool and sandbox functionality. Bump the client protocol without old-host fallback.
6. Delete obsolete storage, types, tools, configuration, tests and documentation. Run full regression, strict type checks, lint, import boundaries and production build. Classify every remaining session identifier; connection, terminal and dependency sessions remain only where those actual semantics apply.

## Highest-risk dependencies

Runner checkpoints and uncertain effects; memory journal and Dream cursor; cancellation and process ownership; tool scope and source authority; Cron/trigger retry identity; WebSocket streaming/completion; settings and channel composition importing obsolete UI helpers. Tests for obsolete conversation behavior must be removed or replaced with observable Agent/Event/Run contracts, without suppressing type errors or excluding supported runtime code.

## Implemented so far

API: AgentInput-only execution, no session route, per-session lock, automatic history import or result projection. The obsolete routing parameter receives a client error. Authentication precedes parsing/upload handling.

SDK: all execution methods use AgentInput. Removed SessionClient, SessionInfo, SessionSnapshot, ingest/export/restore/reset/delete helpers, persisted-session callbacks and Session compaction methods. Ephemeral is a Run option with process cancellation and no durable execution record. Streaming reports runtime after admission, preserves tool/text events and propagates failure/cancellation.

AgentStore: identity/state, Events and Runs are the only tables created in new databases. Recent context and journal work derive from Run records; removed duplicate interaction storage and legacy import APIs. Existing databases/tables/backups are not deleted.

Lifecycle: process_event tracks active calls for shutdown; explicit shutdown preservation leaves recoverable interrupted Runs. Cached results retain their stop reason. Heartbeat no longer selects private notification destinations from legacy session lists or unified-session state.

## Still required before acceptance

AgentLoop now dispatches AgentInput events through PersistentAgent and AgentStore. SessionManager, SessionState, SqliteSessionStore, SessionPolicy, Session keys, generation checks, unified-session behavior, Session tools, legacy Session routes, and Session-based WebUI projections have been removed. The personal WebUI uses protocol v2 and live Agent/Event/Run frames. Remaining technical session identifiers are independent external connections, terminal process sessions, or provider protocol fields.
